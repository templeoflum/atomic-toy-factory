# Atomic Factory

## Purpose

Atomic Factory is a local instrument for turning a compact work order into a playable, one-slider HTML toy through one isolated Codex worker. It emphasizes inspectable iteration, durable provenance, and strong boundaries over throughput or feature breadth.

## Product principles

1. One mechanic, one slider, one focused toy.
2. Worker output is never trusted merely because it completed.
3. Every presented version and the instruction that produced it remain inspectable.
4. Generated work cannot modify the factory or previously presented candidates.
5. The preview cannot reach host controls, credentials, storage, or the network.
6. The application remains buildless and dependency-free unless a recorded decision changes that constraint.
7. Responsive behavior preserves hierarchy and prevents overlap before preserving a particular arrangement.

## Non-goals through local v1

- Cloud hosting or multi-user collaboration.
- More than one concurrent worker.
- Arbitrary generated applications or multiple controls.
- Network-enabled toys.
- A plugin marketplace or remote reference ingestion.

## Authority

Ordinary implementation, testing, documentation, and reversible product decisions may proceed autonomously. Credentials, destructive operations, security-boundary reductions, and meaningful scope changes require Donovan.
