# Architecture and invariants

## Runtime

The application is buildless. `node server.js` starts a localhost HTTP server and one installed `codex app-server` child process. The browser uses static HTML/CSS/JavaScript and Server-Sent Events. There are no npm runtime dependencies.

## Trust boundaries

### Factory

Owns application code, persistent state, saved candidates, work-order metadata, and the app-server connection. Worker sandboxes must never include these locations as writable roots.

### Attempt workspace

Every attempt receives a unique directory. Codex receives `workspaceWrite` with only that directory writable, network disabled, temporary-directory writes excluded, and approval policy `never`.

### Selected reference

A reference is an existing canonical local regular file. It remains outside the attempt writable root and is described to the worker as read-only.

### Candidate store

The factory validates completed output and copies it into a new immutable candidate directory. Rework creates another attempt and another candidate; it never edits a presented candidate.

### Preview

Candidates run in an iframe with only `allow-scripts`, without `allow-same-origin`. The preview response applies a restrictive CSP: no network connections, forms, navigation bases, remote assets, or ancestor outside the factory.

## Protocol

`lib/app-server.js` speaks newline-delimited JSON-RPC over stdio using protocol methods generated by the installed Codex binary. Each attempt starts a fresh ephemeral thread. Status derives from app-server notifications, not timers or simulated progress.

## Persistence

`data/state.json` is the authoritative local state. Writes use a temporary file followed by rename. Schema migrations must be explicit, tested, and create a version backup before altering existing state.

## Invariants

- One active attempt at a time.
- One range slider per accepted candidate.
- No external assets or network-capable APIs in candidate source.
- No candidate overwrites.
- No worker write access outside its attempt.
- Every rework names its parent and retains its correction.
- Terminal status is not reported until the runtime confirms it or restart recovery reconciles it.
